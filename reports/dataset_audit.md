## 7. Duplicate analysis
**File-Level Duplicates:** No exact MD5 file hash duplicates were found on disk.
**MASSIVE PIPELINE LEAKAGE DISCOVERED:** 
While there are no duplicate files on disk, `classify.py` contains a critical bug:
`files = list(cls_dir.glob("*.jpg")) + list(cls_dir.glob("*.png")) + list(cls_dir.glob("*.JPG"))`
Because Windows is case-insensitive, `.glob("*.jpg")` and `.glob("*.JPG")` return the exact same files. Every single `.jpg` image is loaded into the feature matrix **twice**. 
This means 372 physical images became 744 feature vectors. Since duplicates exist before the 80/20 train/test split, identical images are leaking across the training and testing sets, artificially inflating the baseline accuracy to ~98%.

## 8. Class imbalance
There is a severe class imbalance:
- Potato Early Blight: 55.1%
- Potato Healthy: 42.2%
- Tomato classes: ~2.6% combined (only 10 physical images total).
This means the SVM is heavily biased towards Potato and essentially guessing or overfitting the Tomato classes.

## 9. Dataset provenance
**Why were Tomato classes missing from Kaggle?**
The `download_data.py` script searches for exact folder name matches: `"Tomato___Late_blight"` (3 underscores). However, the `emmarex/plantdisease` Kaggle dataset names these folders `"Tomato_Late_blight"` and `"Tomato_healthy"` (1 underscore). Because of this string mismatch, the downloader failed to locate and extract the Tomato images.
The 10 physical Tomato images present are synthetic (`sample_000.jpg`, etc.) generated by the script's fallback function from a previous local run.

## 10. Problems discovered
1. **Critical Data Leakage:** The `classify.py` data loader duplicates every image on Windows due to case-insensitive globbing.
2. **Missing Source Data:** The dataset downloader is looking for the wrong directory names for Tomato.
3. **Severe Imbalance / Synthetic Contamination:** The Tomato classes have only 5 images each, and they are synthetic approximations, not real dataset images.
